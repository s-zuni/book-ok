# 문해력 점검 개선 계획

코드 점검(2026-10-22) 결과를 바탕으로 한 단계별 개선 계획입니다. 각 단계는 앞 단계 위에서만 의미가 있으므로 순서대로 진행합니다.

## 원칙
- 측정할 수 없는 것을 측정한다고 말하지 않는다 (문구·점수·평점 모두).
- 정답, 점수, 저장 여부는 서버가 결정하고 클라이언트 입력은 신뢰하지 않는다.
- 아이 개인정보(이름)는 외부(OpenAI/GA)로 보내지 않는다.

## 이 계획에 포함하지 않은 것 (콘텐츠·운영 작업)
- **지문·문항 확충**: 학년당 2편 → 8편 이상, 영역당 3문항 이상. 사람이 검수해야 하는 교육 콘텐츠라 코드로 대체할 수 없음.
- **문항 응답 로그 테이블과 문항 분석**(정답률·변별도). 확충한 문항이 있어야 의미 있음.
- **읽은 책 제외 처방**(`read_books` ↔ `books.isbn` 조인).
- **GA 동의 배너·개인정보처리방침 개정·스토어 데이터 수집 신고**.
- **권장 속도(WPM) 표의 출처 확보**. 현재 값은 자체 설정이므로 "참고"로만 표기.

## 배포 순서 (반드시 이 순서)
1. `supabase db push` — `20261022120000_literacy_integrity.sql` 적용 (새 Edge Function은 이 테이블/함수가 있어야 제출이 동작)
2. `supabase functions deploy literacy-test`
3. 앱 빌드 전 `npx cap sync` (새 플러그인 `@capacitor/share`, `@capacitor/filesystem` 반영)
4. (선택) 런타임 문항 생성이 필요하면 `LITERACY_ALLOW_RUNTIME_GENERATION=true` — 기본은 꺼짐
